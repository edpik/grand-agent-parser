# Конвертер GSF / GSFX / GSDX / XML → CSV

Онлайн: https://grand-csv-converter.ed-pik.chatgpt.site

Приватный Site открывается под аккаунтом ChatGPT его владельца. Исходный код интерфейса находится в `web/` этого репозитория.

## Как пользоваться

1. Перетащите файлы в область загрузки или нажмите «Выбрать файлы».
2. Нажмите «Преобразовать».
3. Проверьте таблицу. Можно выбрать один файл, найти строки по коду/наименованию и изменить состав CSV.
4. Нажмите «Скачать CSV». Поиск и выбор файла применяются к скачиваемым строкам, а не только к предпросмотру. Пагинация ограничивает лишь число строк на экране.

Для нормативной базы основной режим — «GSDX: записи базы и поиск». Другие варианты: «GSDX: каталог сборников», «GSDX: технические тексты» или «GSDX: реестр блоков». При загрузке только GSDX выбирается режим записей базы. Каталог не подставляется вместо позиций автоматически. Если позиций не найдено, выгрузка записей недоступна и показано предупреждение. Режим «Все XML-поля» включает Content, Zones и ArticleContent. Файлы других типов пропускаются в режимах GSDX; режим позиций сметы не выдаёт каталог за расценки.

Кнопка «Попробовать на примере» загружает искусственную смету из двух позиций. Это демонстрация работы, а не реальная смета.

## Совместимость

| Вход | Что происходит |
|---|---|
| GSFX с открытым Data.xml | Извлекаются позиции `Document/Chapters/Chapter/Position` или доступные XML-поля |
| GSF с XML или ZIP с Data.xml | Читается содержимое независимо от расширения |
| Старый двоичный GSF | Показывается инструкция предварительного преобразования в XML; успешный пустой CSV не создаётся |
| Data.xml.crypt / ZIP с паролем | Явное сообщение о необходимости обычного XML-экспорта |
| XML локальной сметы | Позиции или все XML-поля |
| XML другой структуры | Все XML-поля; не выдаётся за позиции локальной сметы |
| GSDX SDB5 | Записи из CodeIndex, слова Fts2 при наличии, каталог сборников, технические тексты по страницам, XML каталога/зон/оглавлений и реестр блоков; числовые расценки не декодируются |

Для преобразования старого двоичного GSF издатель описывает XML-экспорт и утилиту Repair на Windows: https://66.grandsmeta.ru/upload/iblock/cff/WorkWithXML6.pdf. Переименование файла в `.xml` не преобразует его содержимое.

## Значения в CSV

- Единицы измерения и числовые строки сохраняются из источника. Например, `100 м2` и `2.500000` не заменяются на `м2` и `2.5`.
- Количество берётся из сохранённого `Quantity.Result`, а при отсутствии элемента Quantity — из числового атрибута позиции. Отсутствующий результат не заменяется нулём.
- Формулы не вычисляются и выгружаются отдельно. Одинаковые коды разных позиций не объединяются.
- Стоимостные поля PriceBase/PriceCurr сохраняются без расчёта итоговой сметной стоимости. Дополнительные XML-атрибуты можно включить отдельными столбцами.
- Каждая строка содержит имя источника, его SHA-256 и путь в источнике. В GSDX это имя блока и страница или XML-путь. Номер страницы — порядковый внутри HTML-статьи, не печатный номер сборника.
- Для каталога и технических страниц GSDX сохраняются ID документа, обозначение и папки. У страниц дополнительно сохраняются смещения и длины в распакованном HTML2-блоке. Вложения не выполняются и не выгружаются как страницы. Неизвестные блоки отмечаются как uninterpreted; расчётные данные не подменяются текстом.
- «Все XML-поля» — отдельные строки атрибутов и текстовых узлов с путями, включая поля, отсутствующие в краткой таблице позиций.
- По умолчанию включена защита формул Excel: перед текстом с потенциальным признаком формулы добавляется апостроф. Числовые литералы, включая отрицательные, сохраняются. Если необходимы строго исходные текстовые строки, настройку можно отключить.
- Для ведущих нулей в кодах при импорте CSV в Excel задайте тип столбца «Текст»: сам CSV не определяет типы ячеек.

По умолчанию CSV содержит UTF-8 BOM, разделитель «;» и строки CRLF. Можно выбрать запятую или табуляцию и UTF-8 без BOM.

## Где обрабатываются файлы

Реальные файлы читаются через File API и разбираются в Web Worker на устройстве. Файлы, их содержимое и результаты не отправляются серверу. Демо-файл и скрипты интерфейса загружаются с того же Site. Данные не сохраняются между обновлениями страницы.

Ограничения: до 10 файлов, 256 МиБ на файл, 512 МиБ суммарно, до 64 МиБ распакованного XML, 100 000 позиций/страниц и 400 000 XML-полей. Для GSDX распаковывается не больше 64 МиБ на блок и 256 МиБ суммарно. Обработка одного файла ограничена минутой. Для чрезмерно широкого CSV предлагается отключить дополнительные поля или выбрать вертикальную выгрузку всех XML-полей.

## Локальный запуск из исходников

Нужен Node.js 22+ для сборки. Python используется только как локальный статический сервер.

```bash
cd web
npm ci
npm test
npm run build
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

Откройте http://127.0.0.1:8080. Не открывайте index.html напрямую через `file://`: Worker требует HTTP(S).

Если в релизном ZIP уже есть `web/dist`, сборку можно пропустить:

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory web/dist
```

## Проверки

`npm test` запускает тесты ZIP/CRC, кодировок, точных значений, формул, CSV, неподдерживаемых форматов и DOM-сценарий загрузки/предпросмотра/скачивания. Транспорт Web Worker в DOM-тесте эмулируется; сам конвертер используется настоящий. Это не визуальная проверка в Safari/Chrome.

Реальной незащищённой сметы пользователя и старого двоичного GSF в тестовом наборе нет. GSFX-демонстрация взята из репозитория и проверена по официальной XSD локальной сметы. Применимость сметных данных и арифметика сметы не подтверждаются конвертацией.

Веб-чтение GSDX сверено с Python-парсером на трёх официальных базах: nb105420, nb105421 и nb121019. Исходные базы не включены в репозиторий и релизный ZIP. В автотестах используется синтетический контейнер SDB5.

| Проверенная база | Документов | Страниц | Результат сверки текстов и смещений |
|---|---:|---:|---|
| nb105420 | 134 | 1 169 | Полное совпадение |
| nb105421 | 137 | 1 208 | Полное совпадение |
| nb121019 | 125 | 855 | Полное совпадение |

## Записи GSDX и поисковый индекс (v0.4.0)

`CodeIndex` содержит код и номер записи `DocRows`. Они читаются непосредственно; номера и смещения проверяются. Коды сохраняются в исходном регистре индекса, в том числе строчном. При наличии `FtsWords` и `Fts2\RowN` слова собираются по сохранённым позициям. Повторения сохраняются; пробелы между пропущенными словами не угадываются. В CSV есть число слов, число пропущенных позиций, имя блока и SHA-256 файла.

Это **поисковые слова**, а не исходный текст: нет исходной пунктуации, регистра и слов, исключённых индексатором. Нельзя использовать их как дословные цитаты или исходные числа сметного расчёта. Поля цены, единицы и нормы расхода из таких текстов не вычисляются. Исходные названия и единицы в DocRows, а также GSH-карточки остаются неразобранными; блок DocRows не отмечается как decoded лишь потому, что проверены границы записей.

Если Fts2 нет, доступны только коды (`code_only`), без выдуманных описаний. Если нет CodeIndex/DocRows, список записей пуст: каталог не выдаётся за позиции.

На nb111125 проверены 620 записей, 620 поисковых текстов и 160 799 слов. JS и Python дают одинаковые результаты; связи слов и карточек сверены с группой 7 обратного индекса FtsWordEntries. На nb105420/nb105421/nb121019 прочитаны соответственно 102 864 / 111 583 / 277 928 кодов; Fts2 в этих файлах отсутствует. Пользовательские файлы и полученные CSV не включаются в публичный репозиторий/релиз.
