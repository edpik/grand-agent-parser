# Наблюдения о GSDX SDB5

Это описание обнаруженной структуры для трёх испытанных файлов, не спецификация производителя.

## Внешний контейнер

- Сигнатура: `53 44 42 05` (`SDB`, версия 5).
- Смещение 8: число имён блоков, UInt32 LE.
- Смещение 12: начало таблицы смещений, UInt32 LE.
- Смещение 20: имена; каждое — байт `01`, длина в одном байте, имя CP1251, байт `00`.
- Таблица содержит по 12 байт на имя: UInt64 LE смещения и UInt32 LE размера.
- Реальные имена используют обратную косую черту: `1\Article2`, не `1/Article2`.
- Проверяются границы, уникальность имён, отсутствие наложений блоков и совпадение конца списка имён с началом таблицы.

## Доступные XML и HTML

Для `Content`, `Zones`, `N\ArticleContent`, `N\Article2`: UInt32 LE распакованного размера, затем raw DEFLATE. Требуются точное совпадение размера, конец потока и отсутствие лишних байтов. Подбор смещений/режимов распаковки не используется.

`Content` содержит Region/Folder/Document. Поле `Document.ID` соответствует `N` в имени блока. Отсутствующий ID равен 0 только в проверенных образцах; повторение или неоднозначность отвергаются.

`Article2` после распаковки — контейнер `HTML 02`, а не один HTML-файл:

1. Смещение 5: UInt32 длины контейнера без первых пяти байтов.
2. Смещение 9: `HTML`; смещение 13: UInt32 версии 1.
3. Смещение 33: UInt32 числа страниц; первая страница начинается с 37.
4. Внешняя запись страницы: тег `01`, UInt32 размера (размер включает само поле размера).
5. Вложенная запись: тег `02`, такой же формат размера.
6. Затем UInt64 длины HTML и сам HTML.
7. После HTML два байта флагов: наблюдались `00 01` и `00 00`. Семантика флагов не установлена; они сохраняются.
8. Следует список вложений: тег `01`, размер, число записей. Вложение — тег `01`, размер, UInt32 длины имени, имя CP1251, UInt64 длины данных, данные.

Изображения не сканируются в поиске HTML, не выполняются и не используются для определения значений. Хвост после страниц содержит дополнительные структуры, включая оглавление и CSS; он не считается прочитанным целиком. Его размер и SHA-256 сохраняются, а доступное отдельное ArticleContent читается как XML.

## Не реализовано

`N\Data` начинается с `GSH 03`. У `Resources`, `Works` и некоторых индексов наблюдается собственная таблица записей. Их содержимое не интерпретируется как расценки, цены или нормы расхода. В парсере нет дешифратора, подбора ключей и алгоритма восстановления чисел по похожим данным.

Поддержка открытого XML ФСНБ является отдельным адаптером. Он не делает бинарный GSDX полностью прочитанным.

## Индексы кодов и поиска (v0.4.0)

Наблюдаемые массивы: UInt32 23, Int32 версии, UInt32 числа записей, затем UInt32 смещений относительно начала блока; конец последней записи равен длине блока. Версия 1 прочитана для CodeIndex, DocRows (только границы), FtsWords, Fts2\RowN. Пустой блок может иметь версию -1 и число 0.

CodeIndex: UInt32 длины, байты CP1251 кода, UInt32 номера записи DocRows. FtsWords: UInt32 длины и CP1251 слово. Fts2\RowN: для каждого слова UInt32 ID слова, UInt32 числа вхождений, массив UInt32 позиций. Слова собираются по позиции, повторения сохраняются. Пропуски не заполняются. Валидируются ссылки, размеры записей и отсутствие неоднозначных позиций.

На nb111125 связь каждого слова с карточкой независимо совпала с группой 7 FtsWordEntries (версия 2; в наблюдаемой записи десять списков UInt32 count + UInt32 индексы записей). Обратный индекс использован при ручной верификации, не для восстановления оригинального текста.

Индексы не дают исходных наименований, единиц, цен, расходов или оригинальных HTML-карточек GSH. Их нельзя считать восстановлением бинарных числовых блоков.
