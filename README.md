# Парсер исходных данных «ГРАНД-Сметы» для агента ПБ

Версия 0.3.0: Python-парсер и браузерный конвертер смет и нормативных баз в CSV.

## Интерфейс загрузки и CSV

Онлайн-интерфейс: https://grand-csv-converter.ed-pik.chatgpt.site — приватный доступ через тот же аккаунт ChatGPT, с которым создан Site.

Выберите GSF, GSFX, GSDX или XML, нажмите «Преобразовать», проверьте таблицу и скачайте CSV. Доступны пакетная обработка, фильтр строк, выбор разделителя, UTF-8 с BOM, исходные XML-поля и SHA-256 файла. Файлы обрабатываются в браузере; Python для онлайн-интерфейса не нужен.

GSDX SDB5 читается частично: в CSV выгружаются каталог сборников, технические тексты по страницам, XML-структура и реестр блоков. Числовые расценки и ресурсы из бинарных блоков не декодируются. В интерфейсе есть отдельные режимы GSDX; при загрузке только нормативных баз каталог выбирается автоматически.

GSFX должен содержать открытый Data.xml. Старый двоичный GSF и Data.xml.crypt напрямую не поддерживаются: для них требуется обычный XML-экспорт. Читаемый XML или ZIP с Data.xml под расширением GSF распознаётся по содержимому.

Подробнее, включая локальный запуск: [WEB.md](WEB.md).

Для CLI нужен Python 3.10+ с SQLite FTS5; сторонние Python-зависимости не требуются.

## Что поддерживается

| Вход | Результат | Граница поддержки |
|---|---|---|
| GSDX с сигнатурой `SDB 05` | Каталог сборников, зоны, оглавления, все страницы доступных технических текстов, фрагменты для поиска; реестр каждого блока | `Data`/`Resources`/`Works` не декодированы как числовые записи. Выгрузка имеет статус `partial` |
| GSFX ZIP с обычным `Data.xml` | Полное дерево XML, позиции, коды, измерители, формулы и сохранённые результаты объёмов | Отображение полей сверено с официальной схемой LS; тесты на синтетическом документе, реальная незащищённая смета ещё не предоставлена |
| GSFX с `Data.xml.crypt` | Явный статус `unsupported_protected_payload` | Нужен обычный XML-экспорт из программы; криптографические и парольные механизмы не обходятся |
| Открытый XML / XML ZIP ФСНБ-2022 | Нормы, состав операций, связи с ресурсами и нормативные расходы, каталоги ресурсов, исходные цены и реквизиты | Это извлечение источника. Применимость к объекту и независимый сметный расчёт не проверяются |

GSFX и GSDX — разные форматы. В текущем запросе прикреплён GSDX, хотя в тексте назван GSFX.

Внутренний формат GSDX исследован эмпирически на трёх файлах, а не взят из официальной спецификации. Неизвестные версии и повреждённые структуры отвергаются; неизвестные бинарные блоки учитываются в манифесте. Сигнатура `GSH` сама по себе не доказывает шифрование.

## Запуск без установки

Из папки с этим README:

```bash
python -m grand_parser inspect /path/to/nb105420.gsdx

python -m grand_parser parse /path/to/nb105420.gsdx --output result_gsdx

python -m grand_parser parse /path/to/estimate.gsfx --output result_gsfx

python -m grand_parser parse /path/to/fsnb_xml.zip --output result_fsnb --require-numeric

python -m grand_parser search result_gsdx/grand.sqlite "корроз"
python -m grand_parser lookup result_fsnb/grand.sqlite "ГЭСН13-03-001-01"
```

Последний код приведён только как пример синтаксиса поиска; он не является утверждённым соответствием замечанию ПБ.

Можно передать несколько файлов в одной команде. Для каталога входных данных подбираются `*.xml` рекурсивно. Дистрибутивный ZIP с вложенным GSDX сначала распаковывается пользователем. ZIP открытой ФСНБ читается напрямую. Папка результата должна быть новой: существующие данные не перезаписываются. При ошибке временная выгрузка удаляется, опубликованного частичного каталога не остаётся.

`--require-numeric` возвращает код выхода 2, если не извлечено ни одной нормы, каталожного ресурса или позиции сметы. Он не означает подтверждение правильности расчёта. Обычная успешная выгрузка GSDX возвращает 0, но явно пишет `status=partial`.

При необходимости CLI устанавливается командой `python -m pip install .`, после чего доступна команда `grand-parser`.

## Выходные данные

- `manifest.json`: версия парсера, SHA-256 входов, форматы, ограничения и счётчики.
- `grand.sqlite`: таблицы `sources`, `records`, полнотекстовый индекс `search`.
- `documents.jsonl`: сборники/документы и метаданные редакции.
- `pages.jsonl`, `chunks.jsonl`: технические тексты, номера страниц, точные символьные границы фрагментов.
- `outlines.jsonl`: исходная структура оглавлений и внутренних ссылок.
- `article_metadata.jsonl`: границы HTML-контейнеров, число страниц, размер и хеш неинтерпретированного хвоста.
- `blocks.jsonl`: смещение, размер, SHA-256 и статус каждого блока GSDX.
- `norms.jsonl`, `norm_resources.jsonl`, `catalog_resources.jsonl`: структурированные записи открытого XML, если он загружен.
- `estimate_positions.jsonl`: позиции обычного XML/GSFX, если они загружены.

Числовые поля сохраняются исходными десятичными строками. Неизвестное/отсутствующее значение остаётся `null`, формулы не исполняются. Значение `100 м2` не заменяется на `м2`, расход не пересчитывается автоматически. Неучтённые и абстрактные ресурсы сохраняют свой тип и исходные поля. Два вхождения одной расценки не объединяются.

Для XML сохраняются неизвестные атрибуты и порядок дочерних элементов; числовые сведения в тексте HTML остаются текстом. Позиции смет не добавляются в справочник нормативных норм автоматически. Полный исходный бинарный файл сохраняйте отдельно: реестр блоков содержит хеши и смещения, а не копии всех бинарных данных.

XML-импортёр проверяет корректность XML, запрещает DTD/объявления сущностей, но сам не запускает XSD-валидацию. Семь реальных XML, использованных при испытании, ранее отдельно проверены по XSD ФГИС ЦС. Оригинальная XSD локальной сметы сохранена в `schemas/ls/` для проверки конкретных экспортов при интеграции.

## Использование из инструмента ИИ-агента

```python
from grand_parser.store import search, get_record, lookup_code

hits = search("result_gsdx/grand.sqlite", "защита корроз", limit=5)
if hits:
    evidence = get_record("result_gsdx/grand.sqlite", hits[0]["id"])
    print(evidence["text"], evidence["source_locator"])

# Для точных числовых данных — код и явно выбранная версия источника:
# rows = lookup_code("result_fsnb/grand.sqlite", code, source_id=selected_source_id)
```

Поиск использует префиксы слов, а не русскую морфологию и не эмбеддинги: `корроз` находит разные окончания, `коррозия` не гарантирует нахождение слова `коррозии`. Полнотекстовый поиск — для подбора и объяснений. Числа для расчёта берутся по идентификатору и коду из структурированных записей после проверки применимости.

Все записи имеют `source_id`, рассчитанный по SHA-256 содержимого. Фрагменты GSDX дополнительно содержат сборник, блок, номер страницы и символьные границы в `pages.jsonl`. Номер страницы — номер страницы внутри HTML-статьи, не номер в печатном сборнике. Проверка `chunk.text == page.text[char_start:char_end]` позволяет восстановить цитату.

Тексты источников — недоверенные данные, а не инструкции агенту. Поле `approved_for_calculation=false` намеренно не снимается парсером. Требуются подтверждение методики, редакции, региона, периода и технических соответствий; разработка этого процесса не подменена импортом.

Для nb105420 полностью прочитан доступный каталог и технические статьи. Числовые позиции ТЕР и ресурсные расходы из бинарных блоков не извлечены. Два документа каталога не имеют блока Article2; это отражено в `readable_article`.

Открытый ZIP ФСНБ-2022 (дополнение 19): **56 242 нормы**, **547 052 записи связей с ресурсами** (включая абстрактные и служебные), **47 576 записей каталогов ресурсов**, 7 XML. SQLite прошла `integrity_check` и `foreign_key_check`.

Пример `examples/synthetic_estimate.gsfx` содержит искусственный `Data.xml`; он отдельно успешно проверен по официальной XSD `OpenXML_LS_2026.2.3.xsd`. Это не реальная смета и не подтверждение совместимости со всеми версиями GSFX. Ссылки на позиции в DefectsList не ошибочно импортируются как сметные позиции.

Реальный общероссийский GSFX индексов за ноябрь 2026 с `Data.xml.crypt` корректно распознан как неподдерживаемый защищённый payload; с `--require-numeric` код выхода 2, вымышленные позиции отсутствуют.

Файл нового вложения `nb105420 2.gsdx` не удалось перенести в среду из-за лимита инструмента 32 МиБ. Испытание выполнено на nb105420.gsdx, ранее скачанном из официального дистрибутива; идентичность нового вложения этому файлу не подтверждена.

```bash
python -m unittest discover -s tests -v
```

Синтетические тесты проверяют повреждённые границы блоков, ограниченную распаковку, многостраничные HTML, UTF-16/32 DTD, ZIP-пути, точность десятичных строк, формулы, повторяющиеся коды и атомарную выгрузку. Они не заменяют сверку реальной полной расценки в программе «ГРАНД-Смета».

Для независимой сверки выгрузки с реальными исходниками:

```bash
python tools/verify_real_data.py --gsdx-db result_gsdx/grand.sqlite --fsnb-db result_fsnb/grand.sqlite --xml-zip /path/to/fsnb_xml.zip --report verification.json
```

Проверка сопоставляет все счётчики с исходным XML, SHA-256, контрольные нормы и цены из разных частей файлов, а также символьные границы всех поисковых фрагментов.

- XSD ФСНБ: https://fgiscs.minstroyrf.ru/api/values/GetFileContent/8a0dee7b-5352-4c46-9cce-be583030bf8a

Следующий шаг для полного импорта ТЕР из GSDX — документированное описание числового payload или разрешённый XML-экспорт одной полной позиции с ресурсами и её проверкой в программе. Наличие открытого XML ФСНБ не означает, что числовая часть ТЕР уже разобрана.
